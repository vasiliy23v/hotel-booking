# Руководство по безопасной миграции данных о кроватях

## 📖 Обзор

Этот гайд поможет вам безопасно перенести данные о кроватях и вместимости из полей `capacity` и `beds` в единое поле `description`.

## 🎯 Цель миграции

**Было (избыточно):**
```typescript
{
  capacity: "1-2 чел.",      // Дублирование
  maxCapacity: 2,            // Реальное число
  beds: ["1 двуспальная"],   // Массив
  description: "..."         // Описание
}
```

**Станет (просто):**
```typescript
{
  maxCapacity: 2,            // Для логики бронирования
  description: "Вместимость: 1-2 чел.\nКровати: 1 двуспальная\n..." // Всё в одном месте
}
```

### Шаг 3: Тестовый запуск (DRY RUN)

Проверьте что миграция работает без ошибок (данные НЕ изменятся):

```bash
npm run migrate:capacity dry-run
```

**Что это сделает:**
- Пройдет по всем комнатам
- Сформирует новые описания
- Покажет результаты
- **НЕ СОХРАНИТ** изменения в БД

**Пример вывода:**
```
=== РЕЖИМ ТЕСТИРОВАНИЯ (DRY RUN) ===

✓ Обновлена комната 101
✓ Обновлена комната 102
✓ Обновлена комната 103
...

📊 Результаты:
  ✓ Обновлено: 45
  - Пропущено: 5
  ✗ Ошибок: 0

💡 Это был тестовый запуск. Данные НЕ изменены.
```

### Шаг 4: Реальное выполнение

Если всё хорошо на предыдущих шагах, выполните миграцию:

```bash
npm run migrate:capacity execute
```

**Скрипт спросит подтверждение:**
```
⚠️  Вы уверены что хотите выполнить миграцию? (yes/no):
```

Введите `yes` и нажмите Enter.

**Что произойдет:**
- Данные из `capacity` и `beds` будут объединены
- Новое содержимое записано в `description`
- **Старые поля НЕ удаляются** (для безопасности)

## 🔍 Troubleshooting

### Проблема: Скрипт не запускается

**Решение:**
```bash
# Проверьте что tsx установлен
npm list tsx

# Если нет - установите
npm install tsx
```

### Проблема: Ошибка подключения к БД

**Решение:**
```bash
# Проверьте подключение
npm run check:db

# Проверьте .env.local
echo $DATABASE_URL
```

### Проблема: Некоторые комнаты не мигрировали

**Причина:** Скорее всего у них не было данных в `capacity` и `beds`

**Решение:** Это нормально, такие комнаты пропускаются

### Проблема: Описание выглядит странно

**Решение:** Можно отредактировать вручную через UI или выполнить SQL:

```sql
UPDATE rooms 
SET description = 'Ваше новое описание'
WHERE number = '101';
```

## 🎨 Кастомизация формата описания

Если хотите изменить формат, отредактируйте функцию `buildNewDescription` в скрипте:

```typescript
function buildNewDescription(room: any): string {
  const parts: string[] = [];
  const beds = Array.isArray(room.beds) ? room.beds : [];

  // Измените формат здесь:
  if (room.capacity) {
    parts.push(`👥 ${room.capacity}`);  // Добавили эмодзи
  }

  if (beds.length > 0) {
    parts.push(`🛏️ ${beds.join(', ')}`);  // Добавили эмодзи
  }

  // Можно использовать другой разделитель:
  return parts.join(' | ');  // Вместо \n
}
```

## 📝 FAQ

**Q: Можно ли откатить миграцию?**  
A: Да, старые поля остаются в БД. Можно просто очистить description.

**Q: Нужно ли удалять старые поля?**  
A: Не обязательно. Можно оставить для истории. Но лучше удалить через месяц.

**Q: Что если у комнаты уже было description?**  
A: Скрипт добавит данные о кроватях к существующему описанию.

**Q: Можно ли запустить миграцию несколько раз?**  
A: Да, но данные могут задублироваться в description. Лучше один раз.

**Q: Как протестировать на dev окружении?**  
A: Используйте отдельную БД для dev и выполните там сначала.
