# Pre-commit хуки

## Обзор

Проект использует [Husky](https://typicode.github.io/husky/) и [lint-staged](https://github.com/okonet/lint-staged) для автоматической проверки кода перед коммитом.

## Что проверяется

При каждом коммите автоматически запускаются:

1. **Автоисправление** - автоматическое исправление простых ошибок форматирования в измененных файлах
2. **Полный линт** - проверка всех файлов на ошибки ESLint
3. **Тесты** - запуск всех unit тестов (без БД, безопасно пропускаются)
4. **Полная сборка** - проверка подключения к БД и сборка приложения

## Установка

После клонирования репозитория или установки зависимостей:

```bash
# Установка зависимостей (husky установится автоматически)
npm install

# Инициализация husky (выполняется автоматически через postinstall)
npm run prepare
```

## Как это работает

### Pre-commit хук

При выполнении `git commit`:

1. **lint-staged** автоматически исправляет простые ошибки в измененных файлах
2. **Полный линт** проверяет все файлы проекта на ошибки ESLint
3. Запускает все тесты (без БД, безопасно)
4. Проверяет подключение к БД и выполняет полную сборку приложения
5. Если все проверки пройдены - коммит выполняется
6. Если есть ошибки - коммит отменяется

## Настройка

### Отключение pre-commit хука

Если нужно временно пропустить проверки:

```bash
# Вариант 1: через переменную окружения
HUSKY=0 git commit -m "wip: work in progress"

# Вариант 2: через флаг --no-verify
git commit --no-verify -m "wip: work in progress"
```

⚠️ **Внимание:** Используйте это только в исключительных случаях!

### Настройка lint-staged

Конфигурация находится в `package.json`:

```json
{
  "lint-staged": {
    "*.{ts,tsx,js,jsx}": [
      "eslint --fix",
      "eslint"
    ]
  }
}
```

Вы можете добавить дополнительные проверки:

```json
{
  "lint-staged": {
    "*.{ts,tsx,js,jsx}": [
      "eslint --fix",
      "eslint"
    ],
    "*.{css,scss}": [
      "stylelint --fix"
    ]
  }
}
```

### Настройка проверок в pre-commit

Отредактируйте `.husky/pre-commit` для изменения порядка или добавления проверок:

```bash
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

# Автоисправление измененных файлов
npx lint-staged

# Полный линт всех файлов
npm run lint

# Все тесты
npm test

# Полная сборка (включая проверку БД)
npm run build:full
```

## Что проверяется

### 1. Linter (ESLint)

- **lint-staged**: Автоматически исправляет простые ошибки в измененных файлах
- **Полный линт**: Проверяет все файлы проекта на ошибки ESLint
- Блокирует коммит при критических ошибках

### 2. Тесты

- Запускает все unit тесты
- Тесты без БД выполняются безопасно
- Тесты с БД пропускаются (без `ALLOW_DB_TESTS`)

### 3. Полная сборка

- Проверяет подключение к базе данных
- Проверяет, что приложение успешно собирается
- Обнаруживает ошибки TypeScript на этапе коммита
- Предотвращает коммит сломанного кода

## Troubleshooting

### Ошибка: "husky command not found"

**Решение:**
```bash
npm install
npm run prepare
```

### Ошибка: "Permission denied"

**Решение (Linux/Mac):**
```bash
chmod +x .husky/pre-commit
chmod +x .husky/_/husky.sh
```

**Решение (Windows):**
- Убедитесь, что Git Bash используется для выполнения хуков
- Или запустите: `git config core.hooksPath .husky`

### Тесты падают в pre-commit

**Проблема:** Тесты не проходят, но вы хотите закоммитить

**Решение:**
1. Исправьте тесты локально
2. Или временно пропустите: `git commit --no-verify`

### Сборка падает в pre-commit

**Проблема:** Приложение не собирается

**Решение:**
1. Исправьте ошибки сборки
2. Проверьте TypeScript ошибки: `npm run build`
3. Не коммитьте сломанный код!

### Pre-commit работает слишком долго

**Проблема:** Проверки занимают много времени

**Решение:**
1. Убедитесь, что проверяются только измененные файлы (lint-staged)
2. Рассмотрите возможность отключения сборки для быстрых коммитов:

```bash
# В .husky/pre-commit закомментируйте:
# npm run build
```

## Рекомендации

1. **Не пропускайте проверки** без необходимости
2. **Исправляйте ошибки** сразу, не откладывайте
3. **Используйте `--no-verify`** только для экстренных случаев
4. **Держите тесты зелеными** - это гарантия качества кода
5. **Проверяйте сборку** перед коммитом в main/master

## Интеграция с IDE

### VS Code

Установите расширения:
- ESLint
- Jest Runner (опционально)

Настройки будут применяться автоматически при сохранении файлов.

### WebStorm / IntelliJ IDEA

1. Settings → Tools → Actions on Save
2. Включите "Run eslint --fix"
3. Husky хуки будут работать автоматически
