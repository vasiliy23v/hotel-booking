# Руководство по установке улучшений стабильности

## ✅ Что было сделано

Реализован комплекс улучшений для повышения стабильности работы системы:

1. **Система уведомлений (Toast)** - пользователь видит результаты своих действий
2. **Retry логика** - автоматическая повторная отправка при ошибках
3. **Логирование действий** - мониторинг активности всех пользователей
4. **Страница просмотра логов** - для анализа проблем
5. **Улучшенная обработка ошибок** - детальная информация об ошибках

## 📦 Установленные зависимости

```bash
npm install sonner  # Библиотека для toast уведомлений
```

## 🗄️ Миграция базы данных

### Важно: Перед выполнением миграции сделайте backup!

### Вариант 1: Через Prisma (рекомендуется)

```bash
# 1. Сгенерировать Prisma клиент с новой моделью
npx prisma generate

# 2. Создать миграцию (для dev окружения)
npx prisma migrate dev --name add_activity_logs

# 3. Для production окружения
npx prisma migrate deploy
```

### Вариант 2: Вручную через SQL

Если Prisma миграция не работает, выполните SQL напрямую:

```bash
# Подключитесь к вашей БД и выполните:
psql $DATABASE_URL -f prisma/migrations/add_activity_logs.sql
```

Или через Neon Dashboard:
1. Откройте [Neon Dashboard](https://console.neon.tech/)
2. Выберите ваш проект
3. Перейдите в **SQL Editor**
4. Скопируйте содержимое файла `prisma/migrations/add_activity_logs.sql`
5. Вставьте и выполните

### Проверка успешной миграции

```sql
-- Проверьте что таблица создана
SELECT * FROM activity_logs LIMIT 1;

-- Проверьте индексы
SELECT indexname FROM pg_indexes WHERE tablename = 'activity_logs';
```

## 🔧 Troubleshooting

### Проблема: Ошибка при миграции БД

**Решение:**
```bash
# Проверьте подключение к БД
npx tsx scripts/check-db-connection.ts

# Если не помогло, примените SQL вручную
psql $DATABASE_URL -f prisma/migrations/add_activity_logs.sql
```

### Проблема: Toast не появляются

**Решение:**
1. Проверьте что `<Toaster />` добавлен в `app/layout.tsx`
2. Проверьте что `sonner` установлен: `npm list sonner`
3. Перезапустите dev сервер

### Проблема: Страница логов не открывается

**Решение:**
1. Проверьте что вы вошли как менеджер/developer
2. Проверьте что миграция БД выполнена
3. Проверьте логи в консоли браузера (F12)

### Проблема: Логи не сохраняются

**Решение:**
1. Проверьте что таблица `activity_logs` существует:
   ```sql
   SELECT COUNT(*) FROM activity_logs;
   ```
2. Проверьте права доступа к таблице
3. Проверьте Function Logs в Vercel Dashboard

### Проблема: Старый код не использует новый API клиент

**Решение:**
Новый API клиент используется автоматически через `lib/api.ts`.
Все существующие вызовы `api.updateRoom()`, `api.createRoom()` и т.д. автоматически получают retry логику и toast уведомления.

## 📊 Мониторинг после установки

### Что проверять первые дни:

1. **Количество ошибок** - на `/cms/logs` фильтр "error"
   - Должно быть < 1% от всех операций
   
2. **Время выполнения** - смотрите колонку "Длительность"
   - Создание комнаты: < 500ms
   - Обновление комнаты: < 300ms
   - Получение списка: < 200ms

3. **Активность пользователей** - раздел "Статистика"
   - Кто чаще всего делает ошибки
   - Кто самый активный

4. **Типичные ошибки** - фильтр по "error"
   - Повторяющиеся ошибки требуют внимания

### Vercel Monitoring:

1. **Vercel Dashboard** → **Analytics**
   - Response Time
   - Error Rate
   - Traffic

2. **Function Logs**
   - Deployments → выберите деплой → Function Logs
   - Смотрите на ошибки сервера

3. **Neon Dashboard**
   - Connection Pool usage
   - Slow queries (> 1s)
