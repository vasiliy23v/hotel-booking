# ✅ Чеклист безопасной миграции данных о кроватях

## 📋 Этап 1: Подготовка (ОБЯЗАТЕЛЬНО!)

- [ ] **Создана резервная копия БД**
  ```bash
  # Через Neon Dashboard: Settings → Backups → Create snapshot
  # Или через командную строку:
  pg_dump $DATABASE_URL > backup_$(date +%Y%m%d_%H%M%S).sql
  ```

- [ ] **Понимание что будет изменено:**
  - `capacity` (string) → будет перенесена в `description`
  - `beds` (array) → будет перенесена в `description`
  - `description` → будет содержать всё
  - `maxCapacity` (number) → НЕ изменяется, используется для логики

- [ ] **Проверено окружение:**
  ```bash
  node --version  # >= 18
  npm --version
  echo $DATABASE_URL  # Правильная БД?
  ```

## 🗑️ Этап 8: Удаление старых колонок (НЕОБРАТИМО!)

**⚠️ ВНИМАНИЕ: Это последний шаг, его нельзя отменить!**

- [ ] **Прошло минимум 3 дня с момента миграции**

- [ ] **Создан финальный backup:**

## 🔄 План отката (на случай проблем)

### Если проблемы ДО удаления колонок:

```sql
-- Просто очистить description и данные останутся в capacity/beds
UPDATE rooms 
SET description = NULL 
WHERE description LIKE 'Вместимость:%';
```

### Если проблемы ПОСЛЕ удаления колонок:

```bash
# Восстановить из backup
psql $DATABASE_URL < backup_before_drop_columns_*.sql
```

## 📞 Что делать при проблемах

1. **НЕ ПАНИКУЙТЕ** - данные в backup
2. **Проверьте логи** - `/cms/logs` или Vercel Dashboard
3. **Откатите через backup** если нужно
4. **Исправьте проблему**
5. **Попробуйте снова**

## 📝 Примечания

- Весь процесс может занять 1-2 недели (с периодом наблюдения)
- Торопиться не нужно - лучше безопасно
- Старые колонки можно оставить навсегда если не уверены
- Всегда можно откатить пока есть backup
