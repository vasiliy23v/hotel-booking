# Руководство по тестированию

## Безопасное тестирование базы данных

✅ **ДА, вы можете безопасно тестировать реальную базу данных!**

Тесты используют несколько уровней защиты, чтобы гарантировать безопасность:

### 🛡️ Многоуровневая защита

1. **Уникальные идентификаторы** - все тестовые данные используют префикс `TEST-{timestamp}`
2. **Автоматическое создание тестового отеля** - тесты создают отдельный тестовый отель
3. **Автоматическая очистка** - все тестовые данные удаляются после тестов
4. **Изоляция данных** - тестовые комнаты не конфликтуют с реальными
5. **Явное разрешение** - тесты не выполняются без `ALLOW_DB_TESTS=true`

### ✅ Гарантии безопасности

- ✅ **Реальные комнаты НЕ будут удалены** - тесты удаляют только свои тестовые комнаты
- ✅ **Реальные отели НЕ будут затронуты** - используется отдельный тестовый отель
- ✅ **Уникальные префиксы** - все тестовые данные имеют уникальные идентификаторы
- ✅ **Автоматическая очистка** - все тестовые данные удаляются после тестов

### ⚠️ Рекомендации

Хотя тесты безопасны для реальной БД, **настоятельно рекомендуется** использовать отдельную тестовую БД для:
- Полной изоляции от продакшн данных
- Возможности тестировать деструктивные операции
- Уверенности в безопасности

## Варианты запуска тестов

### 1. Без БД (по умолчанию - безопасно) ✅

```bash
npm test
```

Тесты будут пропущены, БД не будет затронута.

### 2. С тестовой БД (РЕКОМЕНДУЕТСЯ) ✅

**Настройка тестовой БД:**

1. Создайте отдельную базу данных для тестов (например, в Neon создайте новую БД)
2. Примените миграции к тестовой БД:
   ```bash
   DATABASE_URL="postgresql://..." npx prisma migrate deploy
   ```

3. Запустите сервер с тестовой БД:
   ```bash
   # Windows PowerShell
   $env:TEST_DATABASE_URL="postgresql://..."; $env:DATABASE_URL=$env:TEST_DATABASE_URL; npm run dev
   
   # Windows CMD
   set TEST_DATABASE_URL=postgresql://...
   set DATABASE_URL=%TEST_DATABASE_URL%
   npm run dev
   
   # Linux/Mac
   TEST_DATABASE_URL="postgresql://..." DATABASE_URL="$TEST_DATABASE_URL" npm run dev
   ```

4. В другом терминале запустите тесты:
   ```bash
   # Windows PowerShell
   $env:TEST_DATABASE_URL="postgresql://..."
   $env:ALLOW_DB_TESTS="true"
   npm test
   
   # Windows CMD
   set TEST_DATABASE_URL=postgresql://...
   set ALLOW_DB_TESTS=true
   npm test
   
   # Linux/Mac
   TEST_DATABASE_URL="postgresql://..." ALLOW_DB_TESTS=true npm test
   ```

   Или создайте файл `.env.test.local` с переменными:
   ```
   TEST_DATABASE_URL=postgresql://...
   ALLOW_DB_TESTS=true
   ```
   
   Затем запустите:
   ```bash
   npm run test:db
   ```
   
   ⚠️ **Важно:** Убедитесь, что сервер также использует `TEST_DATABASE_URL`!

### 3. С продакшн БД (НЕ РЕКОМЕНДУЕТСЯ) ⚠️

```bash
# Windows PowerShell
$env:ALLOW_DB_TESTS="true"; npm test

# Windows CMD
set ALLOW_DB_TESTS=true
npm test

# Linux/Mac
ALLOW_DB_TESTS=true npm test
```

⚠️ **ВНИМАНИЕ:** Будет показано предупреждение о использовании продакшн БД. Тесты используют уникальные TEST- префиксы, но риск ошибок все равно существует.

## Как работают тесты

### Изоляция данных

Тесты используют уникальные идентификаторы с префиксом `TEST-`:
- `hotelId`: `TEST-hotel-{timestamp}`
- `number`: `TEST-{timestamp}-{suffix}`

Это гарантирует, что тестовые данные не конфликтуют с реальными.

### Автоматическая очистка

После завершения тестов все созданные тестовые комнаты автоматически удаляются через `afterAll` hook.

### Что тестируется

- ✅ Создание комнат
- ✅ Получение списка комнат
- ✅ Фильтрация по hotelId
- ✅ Обновление комнат
- ✅ Удаление комнат
- ✅ Обработка ошибок
- ✅ Параллельные операции
- ✅ Retry логика

## Переменные окружения

| Переменная | Описание | Обязательна | По умолчанию |
|-----------|----------|-------------|--------------|
| `ALLOW_DB_TESTS` | Разрешает выполнение тестов с БД | Да (для тестов с БД) | `false` |
| `TEST_DATABASE_URL` | URL тестовой БД (рекомендуется) | Нет | Используется `DATABASE_URL` |
| `DATABASE_URL` | URL БД (используется если TEST_DATABASE_URL не установлена) | Нет | - |
| `TEST_API_URL` | URL API для тестов | Нет | `http://localhost:3000` |
| `DELETE_TEST_HOTEL` | Удалять ли тестовый отель после тестов | Нет | `false` (остается для повторных тестов) |

## Как это работает безопасно

### 1. Изоляция через уникальные идентификаторы

Все тестовые данные используют уникальные идентификаторы:
- `hotelId`: `TEST-hotel-{timestamp}` (например: `TEST-hotel-1703123456789`)
- `number`: `TEST-{timestamp}-{suffix}` (например: `TEST-1703123456789-create`)

Это гарантирует, что:
- ✅ Тестовые данные не конфликтуют с реальными
- ✅ Можно безопасно запускать тесты параллельно
- ✅ Легко найти и удалить тестовые данные

### 2. Автоматическое создание тестового отеля

Перед тестами система:
1. Проверяет существование тестового отеля
2. Создает его автоматически, если не существует
3. Использует уникальный `hotelId` с префиксом `TEST-`

### 3. Автоматическая очистка

После тестов система:
1. Удаляет все созданные тестовые комнаты
2. Опционально удаляет тестовый отель (если `DELETE_TEST_HOTEL=true`)
3. Логирует все операции очистки

### 4. Защита от случайного запуска

Тесты **НЕ выполняются** без явного разрешения:
- Без `ALLOW_DB_TESTS=true` - тесты пропускаются
- С предупреждениями о типе БД (тестовая/продакшн)

## Рекомендации

1. **Всегда используйте тестовую БД** для разработки
2. **Создавайте резервные копии** перед тестированием на продакшн БД
3. **Проверяйте предупреждения** перед запуском тестов
4. **Используйте уникальные префиксы** (уже реализовано в тестах)

## CI/CD интеграция

Тесты автоматически запускаются при деплое через GitHub Actions.

### Автоматический запуск тестов

При каждом push или pull request:
1. ✅ Запускается линтер (`npm run lint`)
2. ✅ Запускаются тесты (`npm test`)
3. ✅ Проверяется подключение к БД
4. ✅ Собирается приложение
5. ✅ Деплоится на Vercel (только для main/master)

### Workflow файлы

- `.github/workflows/test.yml` - отдельный workflow для тестов
- `.github/workflows/vercel-deploy.yml` - основной пайплайн с тестами и деплоем

### Поведение тестов в CI/CD

В CI/CD окружении:
- ✅ Тесты **НЕ требуют** запущенного сервера
- ✅ Тесты **НЕ требуют** БД (пропускаются без `ALLOW_DB_TESTS`)
- ✅ Тесты проверяют конфигурацию и структуру кода
- ✅ Деплой происходит только после успешных тестов

### Настройка тестов с БД в CI/CD (опционально)

Если хотите запускать тесты с БД в CI/CD:

1. Добавьте `TEST_DATABASE_URL` в GitHub Secrets
2. Тесты будут пытаться подключиться к тестовой БД
3. ⚠️ **Важно:** В CI/CD сервер не запущен, поэтому тесты с БД будут пропущены
4. Это нормально - тесты проверят конфигурацию без реального выполнения

### GitHub Secrets

Для работы пайплайна нужны следующие secrets:

| Secret | Описание | Обязателен |
|--------|----------|------------|
| `DATABASE_URL` | URL основной БД | Да |
| `VERCEL_TOKEN` | Токен Vercel | Да (для деплоя) |
| `VERCEL_ORG_ID` | ID организации Vercel | Да (для деплоя) |
| `VERCEL_PROJECT_ID` | ID проекта Vercel | Да (для деплоя) |
| `TEST_DATABASE_URL` | URL тестовой БД | Нет (опционально) |

## Устранение проблем

### Тесты не выполняются

Убедитесь, что установлена переменная `ALLOW_DB_TESTS=true`:
```bash
ALLOW_DB_TESTS=true npm test
```

### Сервер недоступен

Запустите сервер в отдельном терминале:
```bash
npm run dev
```

### Ошибки подключения к БД

Проверьте:
1. Правильность `DATABASE_URL` или `TEST_DATABASE_URL`
2. Доступность БД из сети
3. Применены ли миграции к тестовой БД

### Тесты падают в CI/CD

1. Проверьте логи GitHub Actions
2. Убедитесь, что все зависимости установлены (`npm ci`)
3. Проверьте, что Prisma Client сгенерирован (`npx prisma generate`)
4. Убедитесь, что `DATABASE_URL` установлен в Secrets

## Примеры использования

### Полный цикл тестирования с тестовой БД

```bash
# 1. Создайте тестовую БД и получите её URL
# Например: postgresql://user:pass@host/db_test

# 2. Примените миграции
DATABASE_URL="postgresql://..." npx prisma migrate deploy

# 3. Запустите сервер с тестовой БД (терминал 1)
DATABASE_URL="postgresql://..." npm run dev

# 4. Запустите тесты (терминал 2)
TEST_DATABASE_URL="postgresql://..." ALLOW_DB_TESTS=true npm test
```

### Быстрый запуск (если TEST_DATABASE_URL уже в .env.local)

```bash
# Терминал 1
npm run dev

# Терминал 2
npm run test:db
```
